# Leak steps

FLOW.md's Leaks rule starts these. A helper whose context doesn't hold the value runs them on the main session's word and reports names and counts only.

1. **Never show the value.** It reaches a command only as a pattern file, through a process substitution fed by the command that reads it from its store, or by the shell's `printf` builtin from a variable that command set in the same shell: `grep -rlFf <(printf '%s\n' "$V") …`, after `[ -n "$V" ]` in the same command, so an empty read stops the search instead of matching every file. It never appears in a command's arguments or text, a script, a file on disk or any output. Search with `grep -l` or `grep -c` only.
2. **Search every copy, of every age:** the output file of the call that showed it and that call's two session-log records; every session log and tool-output folder on the machine; the notes and their `.bak` copies; boards; attachments; agents' scratch folders; worktrees' files, tracked or not, and their commits not yet on the main branch (`git grep -l` on each). Leave out by name (`grep --exclude`, or a `':!*<name>'` pathspec for `git grep`, which matches at every depth) the store it was read from and every credential file: `.env` files, Wisp's `credentials.json` and `oauth-*` sign-in files.
3. **Scrub by swap, the flow's own files only:** this project's agents' session logs (a log whose first record's `cwd`, read alone, is the main checkout or one of its worktrees) and their output folders, the notes, boards, scratch folders and worktrees. Swap a file only once no process has it open (`fuser -s <file>` exits 1); until then it is waiting, and is swapped when the main session says its writer has ended. For each, a program that reads the value from its standard input, never its arguments (a `sed` expression holding it would leak it again), writes the text with `[redacted]` in its place to a new file in the same folder with the same mode. Check the new file: 0 matches, the same line count, and for a `.jsonl` log every line still parses. Then rename it over the original. Keep no copy of the unscrubbed file. A session whose log is scrubbed may be resumed.
4. **What left the machine stays out.** A push, an MR description, a search or a request to a server can't be taken back; replacing the credential is the only fix.
5. **Report** each place by name with its count of files found and scrubbed; the files still waiting, with their session ids, among them the main session's own log when its context holds the value, which waits for as long as its chat runs and which the main session names to the user; the files that aren't the flow's own, by name, for the main session to ask the user before they're scrubbed (FLOW, Asking rule); the commits that hold it, for the merge agent to squash their branch (FLOW, Privacy); and what couldn't be searched: the provider's side, deleted files and removed commits, other machines, encoded or split copies, and any copy left of a value its store no longer holds because it was already replaced.
